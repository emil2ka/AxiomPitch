# Мост PitchFlow

Локальный сервер для хакатонного MVP. Он хранит презентации и итоги,
переключает слайды в приложении, где идёт показ, и поднимает чёлку
с аватаром поверх экрана аудитории.

Жест по-прежнему распознаёт вкладка спикера. Камера, кадры, MediaPipe и
GestureEngine остаются в браузере. На сервер приходят только координаты
позы, команды и состояние сессии. Видео не передаётся, второй захват
камеры запрещён.

## Авторизации нет — осознанно

Это доверенный локальный процесс на время хакатона. Он слушает только
`127.0.0.1:8787`, отвечает только страницам Vite (5173) и preview (4173),
отклоняет чужой `Origin` и чужой `Host` и принимает JSON только
с `Content-Type: application/json`. Логина, токенов, пользователей и облака
нет. Не открывай порт в сеть и не запускай мост на общей машине: любой
локальный процесс может листать слайды и читать сохранённые PDF.

## Запуск

```bash
npm run server     # мост на http://127.0.0.1:8787
cp .env.example .env.local
npm run dev        # вкладка спикера знает мост через VITE_API_BASE_URL
npm run overlay    # Electron-чёлка поверх экрана аудитории
```

Мосту нужен Node.js 22.13+ (встроенный `node:sqlite`); проверено на 26.4.
Данные лежат в `server/data/`: `pitchflow.db` и `presentations/<id>.pdf`.
Папка не попадает в git. Переменные: `PITCHFLOW_PORT` и `PITCHFLOW_DATA_DIR`
для сервера, `PITCHFLOW_ORIGIN` (адрес Vite) и `PITCHFLOW_BRIDGE` (адрес
моста) для чёлки.

## Цели

| Цель         | Как листает                                              | Номер слайда                |
| ------------ | -------------------------------------------------------- | --------------------------- |
| `pitchflow`  | Колода внутри вкладки, как раньше (`goTo`)               | из вкладки                  |
| `keynote`    | AppleScript `show next` / `show previous`                | `slide number` из Keynote   |
| `powerpoint` | AppleScript `go to next/previous slide` активного показа | `slide index` из PowerPoint |
| `chrome`     | Стрелка через System Events, только когда Chrome впереди | нет: вкладка ведёт оценку   |
| `frontmost`  | Стрелка через System Events в явно подключённый процесс  | нет: вкладка ведёт оценку   |

Если показ в Keynote или PowerPoint не запущен, мост отвечает «Не запущен
показ слайдов в Keynote.», а не молчаливым успехом. Стрелки не уходят, если
впереди другое приложение, Terminal, iTerm, Finder, окно чёлки или вкладка
PitchFlow. Удержание ладони (`toggle`) — это блокировка жестов: в
приложение она не отправляется никогда. Когда жесты заблокированы, мост
не листает ни по WebSocket, ни по HTTP.

Когда приложение не сообщает номер (`readState` вернул `null`), мост отдаёт
`slideIndex: null`. Вкладка сдвигается на шаг сама и показывает «≈» рядом
с номером, чтобы оценка не выглядела настоящим номером слайда.

Разрешения macOS: для Keynote и PowerPoint — «Автоматизация» для терминала,
в котором запущен мост (macOS спросит при первой команде). Для `chrome` и
`frontmost` — ещё и «Универсальный доступ». Без него мост так и пишет:
«Нужен Универсальный доступ…».

Вкладка спикера должна оставаться видимой на ноутбуке: свернутая вкладка
тормозит камеру. В Keynote отключи дисплей докладчика или перенеси его,
чтобы он не закрыл PitchFlow.

## HTTP

| Метод и путь                         | Что делает                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------- |
| `POST /api/presentations`            | multipart, поле `file`. PDF до 30 МБ и 60 страниц, страницы считает PDF.js |
| `GET /api/presentations`             | `{ items: [{ id, name, url, pageCount, notes, createdAt }] }`              |
| `GET /api/presentations/:id`         | одна презентация                                                           |
| `GET /api/presentations/:id/file`    | сам PDF, только для запросов с этого компьютера                            |
| `PATCH /api/presentations/:id/notes` | `{ notes: string[] }`, длина равна `pageCount`                             |
| `POST /api/sessions`                 | SessionResult и необязательный `presentationId`                            |
| `GET /api/sessions?limit&offset`     | `{ items, total, limit, offset }`, новые сверху                            |
| `GET /api/targets`                   | `{ current, targets, apps }`: цели, их доступность, процессы               |
| `POST /api/targets/connect`          | `{ app, process? }`; `process` нужен для `frontmost`                       |
| `DELETE /api/targets/current`        | отключить цель                                                             |
| `POST /api/control`                  | `{ gesture: "next" \| "previous", locked? }`; `toggle` — 400               |
| `GET /api/control/state`             | `{ app, connected, slideIndex, slideCount, locked }`                       |
| `GET /api/overlay`                   | `{ visible, displayId, displays, shellConnected }`                         |
| `POST /api/overlay`                  | `{ visible, displayId? }` поднимает или прячет чёлку                       |

Ошибки — `{ error }` с коротким текстом на русском. `POST /api/sessions`
отклоняет тело, если `duration` не равна сумме `perSlide`, `mode` не
`rehearsal`/`live`, в `commands` не ровно `next`/`previous`/`toggle`, в
`corrections` есть код не из `frame`, `lost-hand`, `palm`, `edge`,
`horizontal`, `wider`, `steady` или есть лишнее поле. Время сохраняется как
его измерила вкладка; паузы уже исключены, отдельного поля для них нет.
Повторный `id` — 409. `POST /api/control` отвечает 409, если жесты
заблокированы, цель не подключена или приложение отказалось листать.

## WebSocket `/live?role=speaker|overlay|shell`

| Сообщение  | Кто шлёт       | Поля                                                              |
| ---------- | -------------- | ----------------------------------------------------------------- |
| `frame`    | вкладка        | `time, pose, hands, poseWorld?, handWorlds?, handLabels?, handScores?` |
| `command`  | вкладка        | `gesture: next \| previous \| toggle, locked`                     |
| `session`  | вкладка        | `stage, mode, index, slideCount, durationMs, id?, overlayEnabled?, overlayDisplayId?` |
| `target`   | мост           | `app, label, connected, slideIndex, slideCount, gesture?, error?` |
| `overlay`  | мост           | `visible, displayId`                                              |
| `control`  | мост → вкладка | `gesture`: шаг колоды PitchFlow по `POST /api/control`            |
| `hello`    | мост           | снимок при подключении: `locked, session, overlay`                |
| `displays` | Electron       | список дисплеев для выбора `displayId`                            |

`frame` приходит с частотой камеры (около 14 Гц), координаты округлены до
четырёх знаков. Мост пересылает его только чёлке и отбрасывает всё, кроме
точек позы. `command` с `next`/`previous` листает внешнюю цель ровно один
раз; после шага мост шлёт `target`. Чёлка только рисует и ничего не
отправляет.

## Проверено

Автотесты (`npm test`, без камеры и без живого Keynote): отклонение
не-PDF, файла больше 30 МБ и PDF на 61 страницу; сохранение маленького PDF;
проверки SessionResult; фейковая цель получает `next` и `previous` ровно по
одному разу; `toggle` не листает; блокировка гасит шаг; `frontmost` не шлёт
клавишу чужому процессу; `readState: null` не превращается в номер Keynote.

Руками на MacBook (macOS 26, один встроенный дисплей). Keynote и PowerPoint
на этой машине не установлены, поэтому их AppleScript руками не проверен.
Проверено:

- Цель `pitchflow`: стрелки и `POST /api/control` листают колоду вкладки,
  `locked: true` даёт 409, `toggle` — 400.
- Полный путь жеста в браузере со скриптованными точками кисти вместо
  камеры и фейковой целью Keynote на мосту: вправо — один `next`, влево —
  один `previous`, удержание блокирует, шаг при блокировке не доходит до
  цели, второе удержание разблокирует. «Завершить» сохраняет сессию,
  `GET /api/sessions` отдаёт `mode`, `duration`, `perSlide`, `commands`,
  `corrections`.
- `frontmost` с подключённым Spotify, когда впереди другое приложение:
  клавиша не отправлена, вкладка показала причину.
- Чёлка: окно 320×96 на уровне screen-saver по центру дисплея. Пока другое
  приложение было в полноэкранном Space, окна остальных программ ушли с
  экрана, а чёлка осталась видимой (проверено по CGWindowList). Страница
  чёлки рисует аватар через WebGL, получает позу, замок и факт сессии.

В текущей версии отступа нет: на MacBook верх окна совпадает с верхним краем
экрана. Чёрный корпус продолжается за физический вырез, а аватар и крестик
располагаются ниже него; на экране без выреза добавочная высота равна нулю.
Геометрия выреза читается Swift-помощником AppKit, который `npm run overlay`
компилирует через установленный `xcrun swiftc`. По умолчанию выбирается MacBook;
другой экран и работа без чёлки доступны в настройках студии. Кликабелен только крестик.


После переноса интерфейса размер чёлки — 220×80; внешний вид взят из
дизайн-копии. Описанная выше ручная проверка 320×96 относится к версии
до переноса. Текущие проверки и решения: [перенос дизайна](../docs/design-integration.md).
