# AxiomPitch

Продуктовое имя — PitchFlow. Веб-помощник для презентаций, питчей, лекций
и репетиций.
Главный интерфейс управления — чёрная чёлка у верхнего края экрана с синим
3D-аватаром: округлой головой, светлыми глазами и маленькой улыбкой и двумя объёмными ладонями.
Аватар виден сразу, а после включения камеры повторяет движения. Камера становится пультом,
а короткий синий импульс подтверждает команду.

## Что работает в MVP

- Настоящий 3D-аватар на Three.js: округлая голова, глаза, улыбка и ладони с пятью пальцами.
- Голова поворачивается по точкам позы; кисти разворачиваются в трёх измерениях по мировым координатам MediaPipe. Пальцы сгибаются по суставам.
- Спокойная поза без камеры, моргание и локальный отклик на команду.
- Распознавание в Web Worker: вычисления не блокируют интерфейс.
- Три команды: ладонь вправо, влево и удержание открытой ладони.
- Калибровка кадра и последовательное обучение трём командам.
- Защита от повторных срабатываний и блокировка для свободной жестикуляции.
- Режим «ошибка» с конкретными подсказками.
- Загрузка PDF до 30 МБ / 60 страниц, демо-презентация, заметки спикера.
- Отдельное синхронизированное окно аудитории без камеры и подсказок.
- Таймер, лимит времени, пауза и завершение выступления.
- Итоги: время по слайдам, число команд и подсказок, экспорт JSON.
- Последние 10 сессий на устройстве в localStorage.
- Локальный мост (`server/`): жест листает Keynote, PowerPoint, Google Slides
  в Chrome или другое приложение, а чёлка с аватаром висит поверх показа
  на экране аудитории (`overlay/`, Electron).
- Сервер хранит PDF, заметки и итоги в SQLite; без него всё работает
  в браузере, как раньше.
- Адаптивный интерфейс и поддержка reduced motion.

## Запуск

Node.js 22.12+ и npm (проверено на Node.js 22.23.1).

```bash
npm ci
npm run dev
```

При установке скрипт `postinstall` копирует WASM из установленной версии
MediaPipe и загружает две готовые модели с официального хранилища Google.
Для первой установки нужен интернет; после неё распознавание использует
локальные файлы из `public/vision/`. При прерванной загрузке:

```bash
npm run setup:vision
```

Открой адрес из терминала (обычно `http://localhost:5173`). Для работы камеры
нужны разрешение браузера и HTTPS либо localhost. Рекомендуется актуальный
Chrome или Edge с поддержкой WebGL, OffscreenCanvas и Web Workers.

```bash
npm run build
npm run preview
npm test
npm run lint
```

Мост и чёлка поверх показа (macOS, Node.js 22.13+):

```bash
cp .env.example .env.local   # VITE_API_BASE_URL=http://127.0.0.1:8787
npm run server               # мост на 127.0.0.1:8787, данные в server/data/
npm run dev
npm run overlay              # Electron-чёлка поверх экрана аудитории
```

Подробности, API и разрешения macOS — в [server/README.md](server/README.md).

Сборка включает TypeScript и подготовку моделей. Для размещения достаточно
статического HTTPS-хостинга каталога `dist/`; сервер для распознавания не нужен.
Не удаляй `dist/vision/` — это локальные модели и WASM.

## Полный сценарий

1. Оставь демонстрационную презентацию или загрузи PDF.
2. Нажми «Включить камеру», разреши доступ и пройди короткое обучение.
3. При необходимости открой «Экран аудитории» и перенеси его на второй монитор.
   Браузер должен разрешать всплывающие окна. Кнопка полноэкранного режима
   находится в окне аудитории. С запущенным мостом кнопка ещё и поднимает
   чёлку поверх экрана аудитории.
   Показываешь из Keynote, PowerPoint или Google Slides? Запусти мост,
   выбери приложение в блоке «Где листать слайды» и нажми «Подключить».
   Тогда аудитория видит само приложение, окно аудитории не открывается,
   а чёлка лежит поверх показа.
4. Выбери режим и лимит, нажми «Начать выступление».
5. Переключай слайды жестами. Для свободной жестикуляции заблокируй управление.
6. Нажми «Завершить»: появятся итоги. Их можно скачать и открыть в истории.

Ручные кнопки и стрелки клавиатуры доступны как резервный способ управления.

## Жесты

| Движение                                          | Действие                   |
| ------------------------------------------------- | -------------------------- |
| Поднять открытую ладонь до плеча, провести вправо | Следующий слайд            |
| Поднять открытую ладонь до плеча, провести влево  | Предыдущий слайд           |
| Поднять открытую ладонь и держать 1,5 секунды     | Блокировка / разблокировка |

Направления соответствуют зеркальному отображению камеры. После команды нужно опустить
руку перед следующей попыткой. Удержание ладони работает и при блокировке:
так можно снова включить команды. Ползунок «Размах жеста» меняет требуемую
длину движения относительно ширины плеч.

Обычную жестикуляцию нельзя надёжно отличить от команды только по намерению
человека. Поэтому руки ниже плеч не запускают команды, после успешного жеста
нужен сброс, а для свободной жестикуляции предусмотрена блокировка.

## Режим «ошибка» — обязательный твист

Команда реализовала собственную логику поверх точек MediaPipe:
открытость ладони, высота относительно плеч, траектория, размах,
время удержания, повторный взвод и задержка между командами.

Примеры конкретных подсказок:

- Согнутые пальцы: «Раскрой ладонь: выпрями четыре пальца».
- Неполная траектория: «Проведи рукой дальше вправо за одно движение».
- Диагональное движение: «Веди руку горизонтально, на одной высоте».
- Ладонь у границы: «Отведи руку от края кадра, чтобы вся ладонь была видна».
- Потеря ладони: «Держи ладонь целиком в кадре до конца движения».
- Неудачное удержание: «Останови ладонь и держи её неподвижно».

Потеря человека в кадре обрабатывается отдельно. Повторяющиеся подсказки
учитываются в итогах с ограничением частоты. В режиме «Выступление»
постоянные статусы сокращены; подсказки всегда остаются на экране спикера.

## Стек и структура

React 19 + TypeScript + Vite; Tailwind CSS / CSS; MediaPipe Tasks Vision;
Three.js / WebGL (аватар); Motion; PDF.js; Lucide React.

```text
src/components/     чёлка, слайды, экран аудитории
src/hooks/          камера и жизненный цикл ресурсов
src/lib/            3D-сцена, жесты, PDF, типы, учёт времени
src/workers/        обработка кадров MediaPipe
server/             локальный мост: SQLite, PDF, WebSocket /live, цели
overlay/            Electron-окно чёлки поверх экрана аудитории
scripts/            подготовка моделей и WASM
tests/              распознавание, время, сервер и мост (без веб-камеры)
```

## Данные и ограничения

Кадры камеры обрабатываются только в браузере и никуда не отправляются.
Без моста PDF, заметки и история живут только в браузере; очистка данных
браузера удалит историю. С мостом копия PDF, заметки и итоги сохраняются
в `server/data/` на этом компьютере, а локальная история остаётся основной.
Мост получает только координаты позы, команды и состояние сессии. Он
слушает только 127.0.0.1 и работает без авторизации: это доверенный
локальный процесс на время хакатона.

Без моста чёлка живёт внутри веб-приложения. С мостом и `npm run overlay`
она висит поверх полноэкранного Keynote, PowerPoint или другого показа.
Zoom и другие программы по-прежнему не управляются.
В MVP не оцениваются эмоции, уверенность, качество речи или содержимое питча.
Поворот головы приблизительно оценивается по точкам позы. Глаза — анимация
персонажа, а не распознавание взгляда или эмоций. Сегментация отключена: для
3D-аватара передаются только координаты, без пиксельной маски человека.

## Проверка

37 автоматических тестов: направления команд, удержание, блокировка и
разблокировка, повторный взвод, игнорирование опущенных рук, конкретные
подсказки, потеря отслеживания, корректный учёт времени без пауз, повороты головы и кистей, устойчивость к некорректным точкам.
Для моста: отклонение не-PDF, файлов больше 30 МБ и длиннее 60 страниц,
проверка SessionResult, фейковая цель получает `next`/`previous` ровно
по одному разу, `toggle` и блокировка не листают, `frontmost` не шлёт
клавишу чужому процессу, неизвестный номер слайда не выдаётся за настоящий.

Мост проверен руками на MacBook без Keynote и PowerPoint: их AppleScript
руками не проверен. Сценарий «вправо, влево, удержание, шаг при
блокировке, второе удержание» прошёл на цели `pitchflow` и на фейковой
цели Keynote (точки кисти подставлялись вместо камеры). Чёлка оставалась
на экране, пока другое приложение было в полноэкранном Space. Подробно —
в [server/README.md](server/README.md#проверено).

Дополнительно проверены в браузере: PDF с кириллицей, окно аудитории,
пауза/завершение/история, запуск обеих моделей в Worker, 3D-аватар до включения
камеры, отслеживание по контрольному видеопотоку, блокировка и возврат в
спокойную позу, отсутствие ошибок JavaScript и
горизонтального переполнения на мобильном экране. Финальная ручная проверка
жестов нужна на камере выступающего с его освещением и расстоянием.
