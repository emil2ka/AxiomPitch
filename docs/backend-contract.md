# Предлагаемый контракт для разработчика бека

Этот документ описывает следующую интеграцию. Эндпоинты ещё не реализованы,
а текущий фронт не отправляет запросов. Серверный стек выбирает разработчик бека.
Кадры камеры на сервер не передаются.

Базовый URL задаётся в `VITE_API_BASE_URL` после подключения API.

## Презентации

- `POST /api/presentations`: multipart/form-data, поле `file` (PDF).
  Ответ: `{ "id": "…", "name": "…", "url": "…", "pageCount": 5 }`.
- `GET /api/presentations`: список доступных презентаций.
- `PATCH /api/presentations/:id/notes`: `{ "notes": ["…", "…"] }`.

Сервер должен проверять тип и размер PDF. Ограничения фронта: 30 МБ и 60 страниц.
Нельзя доверять присланным клиентом метаданным файла или счётчикам как
доказательству достоверности выступления.

## Итоги

- `POST /api/sessions`: объект SessionResult из `src/lib/types.ts`, опционально
  `presentationId` для привязки к презентации.
- `GET /api/sessions`: история с пагинацией.

Пример (все длительности в миллисекундах):

```json
{
  "id": "uuid",
  "name": "Первый питч",
  "startedAt": "2026-09-28T04:00:00.000Z",
  "mode": "rehearsal",
  "duration": 120000,
  "perSlide": [60000, 60000],
  "slideTitles": ["Вступление", "Решение"],
  "commands": { "next": 1, "previous": 0, "toggle": 2 },
  "corrections": { "wider": 1 }
}
```

`duration` равна сумме `perSlide`, паузы исключены. `corrections` содержит
коды `frame`, `lost-hand`, `palm`, `edge`, `horizontal`, `wider`, `steady`.

Идентификацию пользователя и доступ к личным презентациям нужно согласовать
до включения постоянного хранения. Фронт не использует авторизацию в MVP.
