# AxiomPitch: архитектура MVP

## Продукт

Помощник для презентаций, питчей, лекций и репетиций.
Главный элемент — чёрная чёлка у верхнего края страницы. В ней выступающий
видит живую синюю тень своей головы, плеч и рук. Успешная команда вызывает
короткую направленную анимацию; неточный жест — конкретную подсказку.

## Фронтенд

- React + TypeScript: интерфейс и состояния сессии.
- Vite: локальный запуск и production-сборка.
- Tailwind CSS + обычный CSS: стили, адаптивность, чёлка.
- MediaPipe Tasks Vision: точки тела и рук, маска человека.
- Canvas 2D: отрисовка синего силуэта по маске сегментации.
- Motion: короткие анимации интерфейса, с учётом reduced motion.
- PDF.js: загрузка и отрисовка PDF-презентаций в браузере.
- Lucide React: иконки.

Все зависимости установлены. MediaPipe и PDF.js пока не подключены к приложению.

## Целевая цепочка обработки камеры

getUserMedia -> кадр -> MediaPipe -> маска + точки -> Canvas чёлки
                                      |
                                      v
                       собственные правила жестов
                                      |
                                      v
                  команда / конкретная подсказка -> UI

Маска формирует заполненный силуэт, а не скелет. Точки нужны для правил жестов.
Вычисления выполняются локально в браузере. Отправка кадров на сервер в MVP
не планируется. Требуются HTTPS или localhost и разрешение на камеру.

## Три команды

1. Движение рукой вправо: следующий слайд.
2. Движение рукой влево: предыдущий слайд.
3. Удержание открытой ладони: блокировка / разблокировка жестов.

Правила учитывают рабочую зону, величину движения относительно тела,
уверенность отслеживания, выдержку и задержку после команды. Нужно отдельно
проверить доступность разблокировки, когда другие команды заблокированы.

Режим «ошибка»: различать потерю отслеживания и неточную попытку команды;
показывать «Покажи ладонь целиком», «Проведи чуть дальше вправо»,
«Удерживай ладонь неподвижно». Подсказки не должны срабатывать при обычной речи.

## Сценарий MVP

Презентация -> камера -> калибровка -> обучение трём командам -> выступление ->
завершение и итоги: время, время по слайдам, команды и неточные попытки.

## Разделение работы

Фронт: камера, распознавание, собственные правила, чёлка, PDF, таймер,
экран аудитории и локальная статистика.

Бек: хранение презентаций, заметок и истории сессий. Серверный стек выбирает
разработчик бека; интерфейс связи — HTTP API. Никакой сервер пока не создан.

## Ограничения первой версии

Чёлка располагается внутри веб-приложения. Наложение поверх произвольных
программ на компьютере — отдельная задача для desktop-версии.
Нельзя обещать оценку уверенности, эмоций или качества речи по одному силуэту.
